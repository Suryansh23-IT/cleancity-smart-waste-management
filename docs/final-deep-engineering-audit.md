## Directed graph and dispatch verification

- Independent Floyd–Warshall all-pairs oracle in `engineeringAudit.test.ts` covers every bin access and depot pair across six curated cities, five ready cities and the showcase. A hand-built fixture covers an isolated node, missing endpoints, self paths, asymmetric weights, parallel roads, tied routes and invalid weights. Reconstructed road IDs, directed endpoints and sums are compared with the reference distance. City JSON validation separately rejects duplicate identifiers, dangling edges and invalid weights.
- The audit also independently builds each zone's induced directed subgraph and checks **every dispatched leg** for urgency-first, identifier-order baseline and all-bin comparison plans. Each leg equals the shortest modeled distance on that zone's graph. Edge speed or truck speed is used for its travel time. Service, unloading, load, depot return and trip duration are reconciled independently. The engine chooses by distance. Travel time can differ between equal-distance paths.
- An intersection permits a turn when legal edges share a graph node. Other-map renderer tests verify a visual gap at a crossing with distinct nodes. There is no separate turn-cost or turn-prohibition dataset. Partition tests reject cross-boundary shortcuts and trips that can only return through another zone. Truck assignments stay with one depot, and pickup IDs are unique across trips.
- Trip timing and labor are different quantities. Fleet completion uses the latest truck end time and modeled cost uses sum of truck minutes and distance. Same-demand comparisons require matching pickup coverage, allow negative differences and guard zero denominators. The full-round comparator uses identical starting inputs and includes all bins as a hypothetical service policy.
- Forecasts use recent valid post-pickup fill growth to estimate time to both collection and urgent thresholds. Regression coverage includes stale, duplicate or insufficient history, no-growth inputs and reset after collection. Forecasts remain modeled estimates. The existing what-if screens use alternative inputs without changing the active run.

### Exact showcase check

The TEST snapshot contains 92%, 88%, 84% and 80% at BIN-001–004. BIN-005–010 are 19–24%, below the 80% cutoff. The configured truck carries 4 bin units. The four eligible loads total **3.44 units**. The engine picks **001 → 003 → 004 → 002**, then returns and unloads. Exhaustive enumeration of **192** pickup-order and unload-split schedules found a minimum of **3.546667 modeled km**. The current trip matches it to floating-point precision. Another tied order is 001 → 002 → 004 → 003. This equality applies to this snapshot and these inputs.

The prior 3-unit setup gave a 6.133333 km urgency-first plan and a 5.413333 km exact feasible distance across 168 schedules. This demonstrates why shortest legs do not establish optimal pickup order. The new showcase produces **one trip, 23.64 virtual minutes and ₹103.24**, including eight pickup minutes and five unloading minutes. The full-round comparison estimates ₹300.85 for visiting all ten, about ₹197.61 more than the threshold plan. Simulated pickups do not modify frozen sensor provenance or SQLite.
